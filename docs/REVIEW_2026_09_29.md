# Review plan, aset, dan struktur — 29 September 2026

Review titik-waktu atas semua dokumen rencana di repo, dicocokkan dengan kode dan game yang berjalan. Dokumen ini tidak menggantikan [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md); isinya menunjukkan apa yang kurang, apa yang tidak konsisten, dan urutan perapian yang disarankan.

## Metode

- Membaca `README.md`, `plan.md`, `TILES_ROADMAP.md`, dan semua file di `docs/`.
- Membaca source di working tree branch `feat/space-planet-town` (saat review dimulai: 33 file tracked termodifikasi dan 55 file untracked), memetakan import antar modul, dan menghitung literal warna.
- Menginventarisasi isi setiap GLB langsung dari chunk JSON-nya (node, material, atribut, triangle, byte per aset).
- Menjalankan `npm test` (24/24 lolos) dan `npm run build` (lolos).
- Mengambil screenshot di in-app browser (1280×860, tier high) pada dunia lokal: planet Neum Prime, kota New Babylon (fantasy) dan Aegis Citadel (modern). Tab otomatis sering tersembunyi sehingga render loop berhenti, jadi pengujian berbasis waktu tidak dilakukan di browser.

## 1. Ringkasan

1. **Roadmap WB/AA terdokumentasi dengan baik**, tetapi baru fondasinya yang terpasang. WB-05 sampai WB-08 (penghuni, POI, ekonomi, event) belum dimulai; tidak ada modul `households`, `simulation`, atau `economy`.
2. **Belum ada dokumen desain gameplay.** Rencana menjelaskan sistem dunia dan aset secara rinci, tetapi tidak menjelaskan tujuan pemain, loop inti per level, dan progresi. Misi saat ini berupa empat checklist.
3. **Arah visual tidak punya satu kontrak.** `plan.md` (neon sci-fi New Dawn), README Update 2 (UI The1 tanpa glow), dan ASSET_ART_AUDIO_PLAN (stylized mid-poly bertekstur) saling tumpang tindih. Town mode memperlihatkan akibatnya. Usulan kontrak ada di [ART_DIRECTION.md](ART_DIRECTION.md).
4. **Beberapa hal sudah ada di game tetapi belum ada di dokumen mana pun:** Firebase Hosting + Analytics, harness QA browser, dan versi layout kota per save.
5. **Fixture belum bisa direproduksi.** Harness browser memakai dunia apa pun yang ada di localStorage browser. "Fixture seed 993910" di dokumen lama hanyalah dunia yang kebetulan ada saat itu.
6. **Struktur kode dan aset perlu dirapikan sebelum fitur besar berikutnya.** Beberapa file sangat besar, `modes/town/` berisi 30 file datar, ada RNG di tempat yang salah, import sirkular, URL aset tersebar, aset mati di `town.glb`, dan tiga generasi aset dipakai bersamaan (lihat [ARCHITECTURE.md](ARCHITECTURE.md) §13 dan [ASSETS.md](ASSETS.md) §6).

## 7. Urutan perapian yang disarankan

Perapian struktur sebaiknya dilakukan **setelah pekerjaan yang sedang berjalan di-commit**. Saat review dimulai, working tree memuat 33 file tracked termodifikasi dan 55 file untracked. Memindah file di atas perubahan yang belum di-commit akan mencampur refactor dengan fitur dalam diff yang sama.

### Fase 1 — struktur kode, tanpa perubahan perilaku

1. Pindahkan `mulberry32` ke `src/math/random.js` dan perbarui 17 import. Sementara, `mapGenerator.js` bisa me-re-export fungsinya.
2. Pindahkan konstanta skala town (`WATER_Y`, `HORIZON_R`, `CHUNKS`) ke modul sendiri untuk memutus import sirkular `townBuilder` ↔ `farTrees`.
3. Pisahkan `planStreetLights` (data) dari `StreetLighting` (render), supaya `townLayout.js` tidak lagi menarik modul render.
4. Buat satu manifest URL aset di kode, lengkap dengan test bahwa setiap file ada di `public/`.
5. Kelompokkan `src/modes/town/` ke subfolder dan perbarui import di `src/`, 12 import di `tests/*.test.js`, serta 3 import di harness browser:

   ```text
   modes/town/
     TownMode.js
     layout/      townLayout, townPlan, wards, neighbourhoodPlan, vegetation, townGreenery, streetJunctions, (streetLightPlan)
     navigation/  walkNetwork, pedestrianRoutes, trafficRoute, colliders
     render/      townBuilder, groundPaint, groundCover, farTrees, roadMarkings, streetLighting, sky
     people/      crowd, peopleRig, peopleAppearance, peopleMotion, personLifecycle
     vehicles/    vehicle, vehicleKit, fleet
     interior/    interior, interiorLayout
     ui/          hud
   ```

6. Pecah file terbesar secara bertahap, masing-masing dengan regresi harness: `TownMode.js` (view/kamera, kontrol interior, kontrol kendaraan, input), `planetRenderer.js` (terrain, kontur, border, props, rute, awan, kamera, POV), `audio.js` (mixer, musik, ambience, SFX, media), dan `style.css` (token, per mode, komponen).
7. Tambahkan lint/format dan CI (butuh keputusan pemilik proyek).

Verifikasi setiap langkah: `npm test`, `npm run build`, harness `living-town.html` (lifecycle, navigasi, controls), serta tidak ada perbedaan pada layout dan screenshot fixture.

### Fase 2 — pipeline aset

1. Buat manifest untuk semua pack (ID, bounds, footprint, triangle per LOD, material), beserta test ukuran/hash per pack.
2. Keluarkan koleksi Nature lama dari export `town.glb`, dan ambil footprint dermaga/bangku dari manifest.
3. Buat model town-scale untuk semua fallback pack planet, lalu berhenti memuat `assets*.glb` di town.
4. Muat `furniture.glb` dan `interior_atlas.jpg` secara lazy.
5. Migrasikan `town.glb` ke loader v2 dengan material bertoken (AA-01).
6. Sediakan satu palet untuk generator Blender, dan satu perintah build aset yang menjalankan paint → scenery → report dengan versi Blender dan Pillow yang tercatat.

### Fase 3 — art direction

Ikuti AD-0 sampai AD-6 di [ART_DIRECTION.md](ART_DIRECTION.md). Fase ini bisa berjalan paralel dengan Fase 2 setelah AD-0 diputuskan. Sebaiknya jangan dimulai sebelum Fase 1 langkah 1–5 selesai, karena AD-1 menyentuh banyak file yang sama.

### Keputusan yang dibutuhkan dari pemilik proyek

1. Arah visual: *painted diorama* (rekomendasi), stylized PBR penuh, atau tetap campuran.
2. Kapan pekerjaan saat ini di-commit, sebagai titik aman sebelum Fase 1.
3. Tooling: lint/format dan CI.
4. Firebase Analytics: tetap aktif (dengan opt-out) atau dinonaktifkan sampai ada kebijakan privasi.
