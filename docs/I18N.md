# Internationalization

English (US) is the default and the source language. Indonesian (`id`) is the second language.
The language is chosen from `?lang=en|id` (remembered), then `localStorage` (`planet_globe_locale`),
then English. The browser language is not sniffed.

## Where things live

- `src/i18n/index.js`: `t(key, params)`, `setLocale`, `getLocale`, `formatNumber`, `applyDom`.
- `src/i18n/locales/{en,id}/*.js`: flat `'domain.key': 'text'` dictionaries, one file per area
  (core, planet, space, town, home, world, skirmish).
- `src/i18n/locales/id/html.js`: Indonesian text for the static pages. Their English text stays in the
  markup, which is the source of truth (and what crawlers and no-JS visitors see).

## Using it

```js
t('pause.resume')                          // plain
t('planet.flight.over', { city: name })    // {city} placeholder
t('planet.tiles', { count: 3 })            // plural: 'planet.tiles.one' / '.other' (numbers are locale-formatted)
```

Static markup: `data-i18n="key"` (text), `data-i18n-html="key"` (inner HTML), `data-i18n-attr="aria-label:key; alt:key2"`.
Call `applyDom()` once at startup (done in `src/main.js` and `src/skirmish/main.js`).

Module-level data that needs text uses getters (`get label() { return t('...'); }`), see `planetTypes.js`.
Avoid naming a local variable `t` in a file that calls `t()`; import as `t as tr` there.

## Switching language

Game text is built once at load, so changing language reloads the page (the route stays in the hash).
The switch is in the pause menu (P) and in the Skirmish setup drawer.

## Checks

`npm test` runs `tests/i18n.test.js`: both languages define the same keys with the same placeholders,
every literal `t('key')` in `src/` exists, and every `data-i18n*` key in the HTML pages has an Indonesian string.

## Adding a language

Add an entry to `LOCALES`, copy `locales/id/` and translate it, register it in `DICTS`.
Skirmish keeps its military labels (PLAYER PHASE, AP, CP) in English on purpose.
