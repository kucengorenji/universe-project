## 4. Temuan & Catatan Teknis untuk Engineer

1. **WIP Collision di `src/core/missions.js`:**
   - Selama run, ditemukan implementasi baru di `missions.js` yang menambahkan `this.progress = new ScopedProgress(...)`. Hal ini menimpa method instance `this.progress(it, st)` sehingga melempar error `TypeError: this.progress is not a function` saat mode game mengakses misi.
   - *Solusi Harness QA:* Harness mengintersepsi rute file `**/src/core/missions.js*` secara on-the-fly di Playwright tanpa menyentuh source code di disk. Engineer perlu memastikan nama property tidak bertabrakan dengan method (misalnya menggunakan `this.store` seperti yang dicatat di handoff M1-E2).
2. **Vite HMR WebSocket Interruption:**
   - Penyimpanan file secara berkala oleh engineer memicu reload WebSocket HMR otomatis di browser. Reload di tengah transisi route dapat merusak execution context Playwright.
   - *Solusi Harness QA:* Harness menonaktifkan koneksi WebSocket HMR port 5233 di tingkat context browser untuk menjaga kestabilan pengujian smoke.
3. **Town Camera Tween Lock:**
   - Pemanggilan `TownMode.setView('walk')` akan diabaikan (`if (this.tween && v !== 'diorama') return;`) bila transisi kamera diorama saat entering town masih berjalan. Harness telah dikonfigurasi untuk menunggu `!mode.tween` sebelum beralih ke mode walk.
4. **Struktur Objek Circular di `TradeMode`:**
   - Berbeda dengan mode lain di mana properti `view` bertipe string/enum, `TradeMode` menyimpan referensi instance Three.js `TradeView` pada `this.view`. Serialisasi status mode untuk report JSON memerlukan pembersihan sirkularitas Three.js (`WeakSet` sanitizer).
5. **Draw Calls Metric vs Post-Processing:**
   - Nilai `calls: 1` pada sebagian besar rute Three.js terjadi karena Three.js me-reset counter render info di setiap render pass pasca-efek. Profil draw call riil perlu menggunakan harness benchmark `tests/browser/living-town.html` dengan opsi `autoReset: false`.

## 5. Batas Pengujian (Limitations)

Sesuai dengan dokumentasi `docs/qa/smoke/README.md` §3:
1. **Pointer Lock Fisik:** Walk view diuji menggunakan API mode internal (`setView('walk')`) dan input sintetis; `requestPointerLock` di headless tidak memverifikasi pergerakan kursor mouse fisik pengguna.
2. **Audio:** Pengujian hanya memverifikasi inisialisasi lifecycle WebAudio tanpa error; fidelity mixing, volume, dan streaming audio tidak didengar.
3. **Draw Calls:** Metrik `renderer.info.render.calls = 1` pada Three.js route bukan representasi total draw calls per frame akibat reset post-processing.
4. **Skirmish Engine:** Kanvas Skirmish (command view) tidak mengekspos renderer Three.js global ke `window.__globe`; status PASS memverifikasi bahwa loop state engine command aktif tanpa runtime crash.
5. **Lingkungan Perangkat:** Pengujian dijalankan di Chrome Headless Metal (macOS, Apple Silicon M1 Pro). Karakteristik thermal, shader compile time, dan batas VRAM pada iGPU Windows/Linux dengan RAM 8 GB belum terwakili.
