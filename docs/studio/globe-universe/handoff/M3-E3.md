## Cara memecah

Test memakai `TownMode.prototype.enterBuilding/exitBuilding/transition.call(objekPalsu)` dan skrip QA memakai anggota instance (`mode.view`, `mode.tween`, `mode.setView`, `mode.exitBuilding`, `mode.player`, `mode.doors`, ...). Maka metode harus tetap ada di instance, bekerja pada state yang sama. Solusi: **kelompok metode** per tanggung jawab di `src/modes/town/controllers/`, masing-masing satu `class` yang hanya jadi wadah, dicampurkan ke `TownMode.prototype` oleh `mixin()` (`controllers/mixin.js`, menyalin descriptor sehingga getter `fading`, `pixelActive`, `renderCamera` utuh; nama ganda melempar error). Kode metode **dipindah apa adanya** (tanpa menulis ulang), dengan skrip yang memotong class menurut batas anggota dan menghasilkan import tiap berkas dari nama yang benar-benar dipakai.

## Jaminan perilaku

1. **Kode identik:** tiap metode dipindah teks apa adanya oleh skrip; `mixin` melempar error bila ada nama ganda, dan test API memastikan tidak ada nama yang hilang.
2. **Pemeriksa nama tak terdefinisi** (`tests/helpers/undefinedIdentifiers.mjs`, penjelajah scope atas AST dengan parser rollup yang sudah ada di vite): berkas hasil pecahan dan **seluruh `src/`** tidak memakai nama yang belum di-import atau dideklarasikan. Pemeriksa diuji sendiri (menangkap import terlupa, variabel lokal terlupa, nama pada nilai default). Ini penjaga utama untuk pola mixin: import yang terlupa baru gagal saat jalur kode itu pertama kali jalan.

4. **Suite lama:** 333 test sebelumnya lulus tanpa satu assertion pun diubah (termasuk `town-transitions` dan `home-state` yang memanggil `TownMode.prototype.*` dan membuat `TownMode` sungguhan). Dua kali percobaan awal gagal karena kesalahan generator saya sendiri (jalur import TownMode ikut diubah, dan konstanta bersama tidak ter-import); keduanya tertangkap test dan pemeriksa, lalu diperbaiki di generator sebelum hasilnya dipakai.

## Catatan jujur dan risiko

1. **Pola ini memindahkan kode, bukan memperbaiki kopling:** state tetap milik instance town (`this.view`, `this.player`, `this.interior`, `this.builder`, ...). Controller bukan objek dengan state sendiri; satu controller dapat menyentuh state yang lain. Keuntungannya: berkas kecil dan bertanggung jawab tunggal, API tetap, risiko perilaku minimal. Langkah berikutnya yang lebih bersih (controller dengan state eksplisit) mengubah bentuk anggota yang dipakai skrip QA, jadi perlu dikerjakan bersama AGY. Dicatat di ARCHITECTURE §7.4.
2. **`townVehicles.js` 364 baris** mendekati batas 400; bila bertambah, pisahkan lalu lintas (armada) dari menyetir.
3. **`enter()` (±170 baris)** dan `update()` (±80) masih di `TownMode`; keduanya orkestrasi berurutan, tetapi `enter()` dapat dipecah menjadi langkah bernama (muat → bangun scene → orang → HUD) pada giliran berikutnya.
4. **Cakupan probe browser** satu dunia acak di M1 Pro; mode drive hanya dicoba satu mobil; touch/joystick dan pointer lock tidak dijalankan (input keyboard dan mouse tombol saja, sama seperti batas probe sebelumnya).
5. **`tools/qa/journey_e2e.mjs` dan `smoke_routes.mjs` tampak berubah di `git status`**; itu pekerjaan AGY, bukan saya.
