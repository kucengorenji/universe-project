## 1–2. Turunan dengan skrip yang di-commit

- `tools/assets/png.mjs`: pembaca/penulis PNG 8-bit (abu, RGB, RGBA) hanya dengan `zlib` Node (`inflate`, `deflate` level 9, filter adaptif, `crc32`), plus `boxDownsample` = rata-rata bulat tiap blok faktor×faktor per kanal. Tidak memakai `sips` (hasilnya tidak bisa dibuktikan identik) dan tidak memasang apa pun. Deterministik: input sama, byte sama.
- `tools/assets/derive_lowres.mjs` (`node …` menulis, `--check` memeriksa kebaruan): menurunkan 5 file dari PNG yang sudah ada dan menulis `tools/assets/derived.json` (hash sumber, ukuran, hash file, **hash piksel**) dan `src/modes/town/render/paintedMeans.js` (dibuat otomatis).
- `public/textures/skirmish_surfaces_256.png`: 6.004.882 B → **1.521.078 B**. Town sudah mengecilkan tiap lapis 512→256 saat runtime dengan filter kotak 2×2 bulat (`compactTownPaintedSurfaces`); file ini adalah hasil persis itu, dihitung sekali. **Bukti:** `tests/derived-assets.test.js` memasukkan data 512 ke fungsi runtime yang sama (`compactTownPaintedSurfaces`) dan membandingkan dengan file 256 yang dikirim: **0 piksel berbeda di semua kanal**. File sumber tanpa chunk warna (`IHDR,IDAT,IEND`), jadi browser mendekode apa adanya. Skirmish tetap memakai file 512 aslinya.
- **Rata-rata warna tile** (`userData.means`, pembagi bayangan tanah) dihitung loader dari data sumber dengan sampling tiap-7-piksel; dari data 256 hasilnya bergeser hingga **1,3 %** pada satu kanal. Agar tampilan tidak bergerak, angka dari sumber 512 dibuat sekali oleh skrip (`paintedMeans.js`) dan `loadTownPaintedSurfaces(url, { means })` memakainya untuk file 256. Test memastikan modul itu sama dengan hasil hitung dari sumber.
- Manifest: `envSurfacesTown`, `soldierAtlasLow`, `soldierHeadLow`, `soldierAtlasFLow`, `soldierHeadFLow` (semua dirujuk kode; test manifest↔pemakai hijau).

## 4. Tubuh perempuan setelah kota tampil (flag `lazyBodies`)

`loadTownPeople({ low, deferFemale })` (`people/skirmishPeople.js`) hanya menunggu tubuh laki-laki (GLB 5,97 MB + 2 atlas + klip jalan). Tubuh perempuan (GLB 6,04 MB + 2 atlas + klip) dimuat oleh `pack.loadFemale()` yang dipanggil `TownMode.arrived()` (kota sudah tampil) dan ditunggu `enterBuilding` sebelum interior dibuat (penghuni mungkin perempuan). Orang yang tampilannya perempuan **tidak ditampilkan sampai tubuhnya siap, dan tidak diganti orang lain** (`needsFemaleBody(seed)`; identitas Damar tidak pernah berubah). `makeTownPerson` mengembalikan `null` bila tubuh belum ada. Sekitar separuh tampilan adalah perempuan, jadi pada beberapa detik awal sekitar separuh warga belum tampak. Kegagalan memuat dicatat `console.warn` dan kota tetap jalan dengan warga laki-laki saja. `loadTownPeople()` tanpa argumen tetap memuat keduanya (dipakai `tools/qa/cozy_actors.js`).

## 6. Heap Planet 254 MiB

**Ukur:** `Runtime.getHeapUsage` setelah `HeapProfiler.collectGarbage` (nilai mentah `usedJSHeapSize` ikut menghitung sampah): Space 21,2 MiB; Planet **239,7 MiB** setelah GC (264 mentah); kembali ke Space masih 231,6 MiB, lalu Planet lagi 240,1 MiB (plateau, bukan bocor terus-menerus, tetapi tertahan setelah Planet ditinggalkan).
**Sebab:** profil sampling heap (fungsi yang mengalokasikan memori yang masih hidup): `wall` (planetRenderer.js:1198) 108 MiB + fungsi anonim di 1292 (`eachTri` ke `push`) 72 MiB = 180 dari 218 MiB. Itu array JS biasa `land.pos/col/nrm` dan `water.*` di `buildTerrain` (jutaan angka double, 8 byte tiap float, dan menggandakan diri saat tumbuh). Seharusnya sampah setelah `makeGeo`, tetapi closure `this.animatedMaterials.push(...)` dalam fungsi yang sama berbagi satu context V8 dengan variabel `land`/`water`, sehingga array ikut hidup selama planet ada.
**Perbaikan** (`render/floatBuffer.js`, `planetRenderer.js`): `FloatBuffer` (Float32Array yang tumbuh) menggantikan array JS, `makeGeo` mengambil salinan seukuran persis dan **melepas** buffer (`buf.pos = buf.nrm = buf.col = null`). **Hasil:** Planet 239,7 → **61,7 MiB** setelah GC (−178 MiB), puncak mentah 264,3 → 122,7 MiB; Space setelah kembali 54 MiB; Planet lagi 61,7 MiB (plateau). Sisa hidup 37,8 MiB hasil sampling (terbesar `ContourField` 9,3 MiB yang memang dipakai).
**Bukti geometri tidak berubah:** pada dunia seed 424242 (subdivision 5), hash SHA-256 atribut `position`, `normal`, `color` dari `landMesh` (1.322.397 vertex) dan `oceanMesh` (878.586 vertex) **identik** antara kode HEAD (dijalankan dari `git archive` di scratchpad) dan kode baru. Test: `tests/float-buffer.test.js` (3): isi `FloatBuffer` sama bit per bit dengan `Float32Array` dari angka yang sama (5000 vertex, tumbuh berkali-kali), hasil salinan, dan source tidak lagi memakai array JS untuk vertex.

## Catatan jujur dan risiko

1. **Estimasi gzip bukan transfer terukur**; transfer terkompresi nyata per rute tetap menunggu AGY di build/preview dengan kompresi.
2. **Pilihan tier atlas dibuat sekali** saat paket orang pertama dimuat; mengganti preset ke/dari Low di tengah sesi baru berlaku setelah muat ulang. Tier `auto` yang turun ke "low" secara dinamis tetap memakai atlas 2048.
3. **Sekitar separuh warga tidak tampak** (yang tampilannya perempuan) sampai tubuh perempuan siap; di jaringan lambat ini bisa berlangsung beberapa detik setelah kota tampil. Damar bila perempuan juga menunggu (identitasnya tidak berganti). Diukur hanya di localhost.
4. **Total `dist/` naik** (file turunan ditambahkan, file asli tetap karena Skirmish memakainya); yang menurun adalah apa yang diminta pemain saat masuk Town.
5. **Skirmish tidak diverifikasi** terhadap `vcSoldiers.js` (hanya menambah `loadSoldierTemplate`; `loadSoldierTemplates` tidak berubah) dan terhadap `planetRenderer` (tidak dijalankan di Skirmish).
6. **Heap Planet:** setelah meninggalkan Planet, heap tetap 54 MiB vs 21 MiB di boot (data peta/renderer yang sengaja dipakai ulang oleh `PlanetMode`); tidak diselidiki lebih lanjut.
7. `tools/qa/cozy_actors.js` (AGY) memanggil `loadTownPeople()` tanpa argumen: tetap memuat kedua tubuh.
8. Skrip probe (browser, hash mesh, heap) ada di scratchpad, tidak di repo; ratchet byte dan test turunan yang masuk repo.
